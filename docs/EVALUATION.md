# Evaluation plan

No evaluation dataset exists yet, and no accuracy is claimed. This page defines how to build one that can support a claim, and the tools that check it (`eval/`).

## 1. Claim-level dataset: 100 real items

Development items are for tuning. Test items are held out and run once with frozen thresholds. The plan is machine-checked by `eval/plan.json`.

| Code | Category | Dev | Test | Total | Ground truth | Expected verdict | Also acceptable |
|---|---|---|---|---|---|---|---|
| G | Genuine government announcement (PIB release, ministry notice) forwarded as text, screenshot or link | 9 | 21 | 30 | TRUE | GENUINE | UNVERIFIED (counts as a miss, not an error) |
| F1 | False claim with a fact-check record (PIB or an IFCN fact-checker) | 6 | 14 | 20 | FALSE | FAKE | none |
| F2 | False claim with no fact-check in the API (PIB-only debunks, or published after the index cutoff) | 4 | 11 | 15 | FALSE | FAKE | UNVERIFIED |
| R | Recycled or altered image with a known original | 4 | 11 | 15 | FALSE | FAKE | UNVERIFIED |
| V | Video reused from known source material | 2 | 6 | 8 | FALSE | FAKE | UNVERIFIED |
| M | Verified manipulated media (AI-generated image, deepfake video, voice clone) confirmed by a fact-check | 3 | 4 | 7 | FALSE | UNVERIFIED | FAKE |
| U | Genuinely unresolved (no reliable evidence either way) | 2 | 3 | 5 | UNRESOLVED | UNVERIFIED | none |
| | **Total** | **30** | **70** | **100** | | | |

On the test split, 21 items are TRUE, 46 are FALSE (14 + 11 + 11 + 6 + 4) and 3 are UNRESOLVED.

### Required fields per sample (`eval/manifest_template.csv`)

| Field | Content |
|---|---|
| `sample_id` | Prefilled, for example `TEST-R-03` |
| `split`, `category` | Prefilled |
| `input_type` | text, screenshot, image, video, audio, link or mixed |
| `language` | en, hi, te, mixed or other |
| `ground_truth_claim` | TRUE, FALSE or UNRESOLVED (prefilled per category) |
| `media_status` | none, original, recycled, edited, ai_generated, manipulated_video, voice_clone or unknown. This is where **manipulated**, **recycled** and **merely unverified** are kept apart |
| `expected_verdict` | Prefilled per category |
| `claim_text`, `links`, `input_file` | The input exactly as a citizen would forward it. Claim text is transcribed by hand, so OCR is tested separately |
| `original_source` | For R and V: the URL of the original media |
| `evidence_url`, `evidence_publisher`, `evidence_date` | The source that establishes ground truth |
| `in_known_index` | 1 if the item's original was put in the known-debunk index |
| `collected_by`, `collected_on`, `notes` | Audit trail |

### Where to get items, legally

- **G:** pick releases from PIB's own pages (reuse allowed with attribution and accuracy). Write the forward the way people do: a screenshot, a paraphrase in Hindi or Telugu, or an official link.
- **F1, F2, R, V, M:** use fact-check articles found through the Google Fact Check Tools API or on the fact-checkers' sites, plus PIB debunks recorded by hand with a link.
  - Do not bulk-download from Telegram, because its terms prohibit AI use.
  - Keep media private in `data/eval_media/` (gitignored), and link to sources rather than redistributing.
- **Forwarding:** for every media item, also create a real WhatsApp-forwarded copy. Send it to a teammate and save it.
- **U:** local rumours that no reliable source has covered, verified as unresolved by two teammates.

### Split rules

- **Split by story, not by item.** The same claim, image or event never appears in both splits. `eval/validate_manifest.py` rejects shared evidence URLs, claim texts or media files.
- **Index cutoff.** Build the known-debunk index only from dev items and debunks published before a cutoff date. Test F2 items must come after the cutoff.
- **Tune only on dev.** `eval/run_eval.py` refuses the test split without `--frozen`. It records a fingerprint of all thresholds and the git commit.
- **Run the test split once.** If you change anything afterwards, say so, and collect a new test set before claiming numbers.

## 2. Separate benchmarks

These are never mixed with claim verdicts.

| Benchmark | Data | Metric | Tool |
|---|---|---|---|
| Media provenance (reuse) | Test R and V items, with known originals | Accuracy: share where the tools found the known original, confirmed by a human in `provenance_review.csv` | `eval/metrics.py` |
| Provenance robustness | Your own originals, transformed (crop, screenshot, rotate, caption, mirror) plus real forwards | recall@1 with pHash only and with pHash+ORB, wrong-id rate, held-out false matches | `eval/provenance_benchmark.py` |
| AI-image detection | 120 images: dev 20 AI + 20 real, test 40 AI + 40 real, each also really forwarded. AI images are generated by the team with named generators. Real photos are taken by the team | AUC, and TPR and FPR at a threshold chosen on dev | `eval/detector_eval.py` |
| Voice-clone and video-deepfake detection | none | not evaluated. No accessible detector is expected to be reliable (see MEDIA_FORENSICS.md) | n/a |

## 3. Metrics (`eval/metrics.py`)

| Metric | Definition |
|---|---|
| FAKE precision, recall, F1 | Positive is ground truth FALSE. A FALSE item predicted UNVERIFIED counts as a miss |
| GENUINE precision, recall, F1 | Positive is ground truth TRUE |
| False-positive rate | TRUE items called FAKE ÷ TRUE items. **Target: 0** |
| False-negative rate | FALSE items not called FAKE ÷ FALSE items |
| False reassurance | FALSE items called GENUINE ÷ FALSE items. **Target: 0** |
| UNVERIFIED rate | Overall and per category. Reported, never hidden |
| Provenance accuracy | See section 2 |
| Detector metrics | See section 2, kept separate |
| API failure rate | Per tool: AUTH_REQUIRED, BLOCKED, SERVICE_ERROR or RATE_LIMITED runs ÷ all runs |
| Latency | p50 and p95, end to end and fast path (urlscan excluded), plus per tool |

Every proportion is printed with a 95% Wilson interval.

### What these sizes can and cannot support

With 21 TRUE test items:
- Zero false accusations only shows the true rate is probably below about 14% (the rule of three, 3 ÷ 21).
- An observed 90% GENUINE recall has a confidence interval of roughly 71% to 97%.

So the team can say "no false accusations in 21 genuine test items", but not "Satyapan is 99% accurate".

## 4. Commands

```bash
cp eval/manifest_template.csv eval/manifest.csv      # fill it in
python eval/validate_manifest.py eval/manifest.csv
python eval/run_eval.py --split dev                  # iterate on dev
python eval/metrics.py results/eval_dev_<time>
python eval/run_eval.py --split test --frozen        # once
python eval/metrics.py results/eval_test_<time>
python eval/provenance_benchmark.py data/known_media --holdout 10
python eval/detector_eval.py eval/detector_manifest.csv
```

## Satyapan 2.0 additions (1 Nov 2026)

- **Collecting real items:** `scripts/collect_factchecks.py --query "..." --language hi --out eval/candidates_hi.csv` saves REAL Fact Check Tools records (claim, rating, publisher, URL, dates). A team member opens each fact-check, confirms it and copies it into `eval/manifest.csv`. Derived items (a real release with a changed amount, or with "BREAKING TODAY" added) go in with `notes` saying they are derived, and are reported separately from real-world items.
- **Choosing the chat model:** label pairs in `eval/bakeoff_pairs_template.csv` (from the development split only) and run `eval/model_bakeoff.py` with each candidate model. It reports verified quotes, relation and same-subject accuracy, accuracy per language, latency and failures.
- **Metrics added to `eval/metrics.py`:** exact and acceptable accuracy, per-language and per-input-type results, and the external API failure rate, all with Wilson intervals, next to the existing confusion matrix, precision, recall, F1, UNVERIFIED rate and latency.
- **Images:** `audit/image_eval.py --evidence-tiers` counts only matches that can be evidence (exact or modified copies).
